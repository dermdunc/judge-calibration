# Decisions: Judge Calibration

## ADR Log

| Date | Decision | Rationale |
|---|---|---|
| 2026-07-22 | Initial scaffold as factory-output | A provider-agnostic harness for calibrating an LLM judge against held-out human verdicts: multi-persona blind scoring, a hard fail-if-any-persona-flags-a-failure-mode gate, and a not_ready/provisional/calibrated verdict based on measured agreement. |
| 2026-07-22 | Generalized from `local-llm-lab`'s persona-lens engine + verdict-gating harness: `lib/{prompt,parse,panel,fixtures,calibrate}.mjs`, a pluggable `lib/backends/ollama.mjs`, a directory-per-case fixture format, and `fixtures/{attempt-good,attempt-gaming}` (sanitized versions of the lab's own real example) | Kept the mechanism (persona-lens scoring, union-of-failure-modes gate, agreement/false-approval/false-rejection measurement), generalized what was hardcoded to one Terminal Velocity module (rubric text, file layout, a local-only backend). Verified against a real model (`qwen2.5:14b-instruct` via Ollama, already on this machine) throughout the build, not just against fakes - the tool's actual claim (a 3-persona panel correctly distinguishes a real fix from a test-gaming attempt) is only meaningful if demonstrated live. |
| 2026-07-22 | Doubt-driven-development pass (single-model, `Explore` agent) found and fixed 10 issues, the most consequential being a design gap that let "calibrated" be reached without ever testing the judge's ability to reject anything | A fixture set containing only human-pass cases trivially reports 0% false-approval-rate (there were no fail cases to be falsely approved) and could reach `calibrated` — fixed with a `minCasesPerClass` gate forcing `not_ready` when either verdict class is under-represented. Also fixed: one case's model-call failure used to abort the entire multi-case run with no partial results (now per-case isolated, errored cases recorded separately, any error forces `not_ready`); `lib/parse.mjs`'s JSON-extraction fallback claimed "balanced brace" matching but was actually naive `indexOf`/`lastIndexOf` (broke on a stray brace in trailing model chatter — replaced with real brace-depth tracking that also respects JSON string boundaries); a live-run re-check of the fixtures' own internal consistency found `task.md` described a crash mechanism (`TypeError` from sorting mixed `None`/`str` keys) that the single-expense reproduction shown in both `candidate.md` files couldn't actually trigger (`sorted()` on 0-1 elements never compares anything) — rewrote both fixtures around a real three-expense, multi-category list where the described crash genuinely occurs. |
| 2026-07-22 | (Correction to the row above, same reconciliation pass) the `--json=false`/`--help=false` inline-value bug, the `--model --typo-flag` argument-consumption bug, `test/e2e.test.mjs`'s model-not-pulled reachability gap, and the disclosed prompt-injection mitigation in `lib/prompt.mjs` were all findings from the single-model round above, not the cross-model round below — noted here because an earlier version of this log misattributed them | Keeping the correction as its own row rather than silently editing history, matching this project's own "disclosed, not hidden" principle. |
| 2026-07-22 | Cross-model review (`codex exec`, gpt-5.5) found and fixed one more real bug, confirmed by direct execution, across two attempts that both hit this session's tool timeout before producing a formal findings summary | `lib/parse.mjs`'s brace-balance JSON extraction located the FIRST `{` in a model's response and returned as soon as *that* brace pair balanced - so a response like `"prefix {not json} then {"score":0.8,...}"` locked onto the earlier, wrong region (`{not json}`) and never reached the real JSON later in the string, the same failure class the balance-tracking fix was supposed to close, one level deeper. Independently reproduced in both timed-out attempts before either could finish, so treated as confirmed despite neither producing a final report. Fixed by scanning for and trying *every* balanced region in the text in order, not just the first, until one actually parses as a valid judge response - re-verified with a dedicated test and a full E2E re-run against the real model. First Codex attempt (`--sandbox danger-full-access`, needed for real Ollama network calls) was killed by the harness at ~10 minutes; a second, more narrowly-scoped attempt (explicitly told to skip re-running the slow live-model path) was killed at ~7 minutes but reached the same finding via direct execution before being cut off. Not re-attempted a third time given the pattern; the single-model round's 10-issue pass plus this one cross-model-surfaced fix is the coverage this repo shipped with. |
